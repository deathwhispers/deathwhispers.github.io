学会写页面只是开始。真正的实战能力，是把一个需求从评审一路带到提测，并且能稳定通过回归。

## 一、需求评审阶段：先做"可交付拆解"

评审时建议你至少确认这 5 项：

1. 页面入口和路由位置。
2. 涉及的接口列表与字段变更。
3. 权限点和角色差异。
4. 异常路径（空数据、失败、超时）。
5. 验收标准和回归范围。

如果这 5 项不清晰，开发阶段必然返工。

## 二、任务拆解模板（前端视角）

- `页面层`：路由、布局、交互流程。
- `数据层`：类型定义、接口封装、状态管理。
- `规则层`：表单校验、权限控制、错误处理。
- `保障层`：自测脚本、提测说明、回归清单。

这样拆解之后，后端同学可以像写后端任务一样管理前端开发节奏。

## 三、开发阶段建议顺序

1. 先补类型和接口（契约前置）。
2. 再实现页面骨架和数据加载。
3. 再补校验、权限、错误处理。
4. 最后做交互细节和样式微调。

这个顺序能最大化减少"做完 UI 才发现接口不匹配"的返工。

## 四、联调阶段的关键动作

- 明确每个接口的 mock/真实环境地址。
- 对分页、排序、筛选参数做抓包确认。
- 对空值、边界值做专项验证。
- 后端日志和前端请求 ID 建立关联。

建议把联调问题按"接口契约问题 / 前端实现问题 / 测试数据问题"分类记录，避免反复拉扯。

## 五、提测阶段需要交付什么

提测不要只说"已开发完成"，建议附以下内容：

- 功能点清单（对应需求编号）。
- 影响页面与入口路径。
- 影响接口与参数变更说明。
- 自测结果（正常 + 异常路径）。
- 已知风险与暂不处理项。

## 六、一个可复用的提测说明模板

```text
需求名称：
改动页面：
改动接口：
权限影响：
自测结果：
回归建议：
已知风险：
```

## 七、交付后的复盘建议

每次提测后复盘三件事：

1. 哪些问题最早应该在评审阶段就发现。
2. 哪些改动没有模板导致重复劳动。
3. 哪些错误可以被 lint、测试或脚本提前拦截。

连续复盘 3 个需求后，你的前端交付会明显趋于稳定。

## 八、后端同学做前端的成长路径

你可以用这三个里程碑判断自己的阶段：

- `阶段 1`：能按文档完成功能。
- `阶段 2`：能在旧项目中稳定小改并自证质量。
- `阶段 3`：能主导需求拆解、联调节奏和提测质量。

达到阶段 3，基本就具备了"工程化前端协作者"的能力，而不仅是"会写 Vue 语法"。
