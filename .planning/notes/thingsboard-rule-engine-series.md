# ThingsBoard 规则引擎与告警系列大纲

## 系列定位

承接现有七篇“设备接入—遥测展示—远程控制—设备管理”教程，继续使用路灯设备和 `turn`、`light`、`battery`、`latitude`、`longitude` 等字段，深入讲解 ThingsBoard 如何接收、处理、分支路由和转发设备消息。

目标读者已经能在 ThingsBoard 中创建设备，并发送 MQTT 遥测。系列既讲消息流和规则引擎原理，也给出可以复现的配置、验证方法和排障路径。

## 版本与环境约定

- 正式编写每篇实操前，记录测试环境的 ThingsBoard 版本、Community/Professional Edition、部署方式和设备接入协议。
- 仓库现有教程没有明确记录版本，因此不能默认旧截图、菜单名称或节点在当前环境仍完全相同。
- 以作者实际验证的环境为主；对版本或 Edition 有差异的节点、界面和配置，明确标注，不把未经验证的配置写成通用步骤。
- 使用测试设备或测试环境演示规则链修改；不要建议直接替换正在运行的生产 Root Rule Chain。

## 篇目规划

### 第八篇：规则引擎与消息流入门

- **目标**：建立“设备消息进入平台后如何被处理”的整体心智模型。
- **内容**：Rule Engine、Rule Chain、Rule Node、Relation 的职责；遥测消息的 `msg`、`metadata`、`msgType`；消息进入、节点处理、按关系分支、保存/告警/转发的典型路径。
- **实操**：向已有路灯发送一条带 `turn`、`light`、`battery` 的遥测；梳理 Root Rule Chain 的入口和节点，不改动链路；记录环境版本及验证结果。
- **验收**：读者能区分消息体、元数据和消息类型，能解释一次遥测经过哪些处理环节，以及关系标签为何决定后续路径。

### 第九篇：创建规则链并调试消息流

- **目标**：独立创建一条测试规则链，连接节点并观测消息流转。
- **内容**：创建/保存规则链、节点连接、输入输出关系、调试模式；如何把消息路由到测试链，避免破坏默认处理。
- **实操**：用一条明确标记的测试消息验证各节点收到的消息、元数据和分支结果。
- **验收**：能从调试事件确认节点是否执行、输出关系是什么，并安全恢复调试配置。

### 第十篇：遥测过滤、校验与转换

- **目标**：在写入或转发前处理不完整或异常遥测。
- **内容**：字段存在性和数据类型检查、阈值过滤、脚本/表达式转换、补充元数据与字段映射；节点失败时的处理路径。
- **实操**：校验 `battery` 与 `light`，过滤非法值，为通过的数据增加来源或分类信息，并比较处理前后的消息。
- **验收**：正常数据走成功分支，缺字段、类型错误和越界数据走预期的过滤/失败分支；读者能说明数据是否仍被持久化。

### 第十一篇：低电量告警的创建、展示与清除

- **目标**：实现可验证的告警生命周期，而不只是一次阈值判断。
- **内容**：设备/实体告警、告警类型与严重级别、活动告警与清除条件、告警查询和展示；避免每条遥测重复创建告警。
- **实操**：以 `battery` 低于示例阈值为触发条件，发送低电量和恢复电量两组数据，分别验证创建和清除。
- **验收**：告警能关联到正确设备，重复低电量数据不会造成难以理解的告警堆积，恢复条件能结束活动告警。

### 第十二篇：规则链中的失败处理与排查

- **目标**：让异常处理可观察、可定位，不让消息静默丢失。
- **内容**：节点 Failure 关系、规则链执行错误、调试事件、平台日志与队列/连接问题的边界；如何区分设备未上报和规则处理失败。
- **实操**：构造缺字段或错误类型消息，追踪失败节点与关系；修正后重复发送并验证恢复。
- **验收**：能沿着消息路径定位问题，知道应检查设备连接、消息结构、节点配置还是外部依赖。

### 第十三篇：把处理后的设备数据转发到外部系统

- **目标**：将通过校验的路灯遥测安全地交给外部服务。
- **内容**：规则匹配后的数据转发、HTTP/MQTT 等可用集成方式、凭证与连接配置、超时/失败处理、重复投递与幂等注意事项。
- **实操**：按作者已验证的环境选择一种集成方式，将通过过滤的数据转发至测试接收端，并分别验证成功与失败路径。
- **验收**：接收端能确认消息内容和设备来源；凭证不写入公开示例；外部服务不可用时有可观察的失败结果。

## 每篇文章的固定结构

1. 本篇目标、前置条件、测试环境版本和 Edition。
2. 原理说明与消息流示意图。
3. 配置步骤及关键参数解释。
4. 测试输入、预期路径和可观察结果。
5. 常见问题、排查顺序及恢复/回滚方式。
